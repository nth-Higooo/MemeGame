# Troubleshooting

Read the current room state before changing anything. A read-only health response confirms the Worker is reachable; `/api/health` does not probe D1/R2 or prove game health. Record time, room code, phase/version, response `X-Request-Id`, and a safe error code. Never copy Authorization/Cookie headers, WebSocket subprotocols, reconnect credentials, or uploaded passwords into a ticket.

| Symptom                                | Check                                                      | Safe response                                                                                                                                                                                                                                        |
| -------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cannot join                            | Code, `LOBBY`, nickname, player count                      | New joins stop after lobby; names are normalized for case/Unicode/spacing. Choose another nickname or use the original browser to reconnect. A full room caps at 50; do not bypass by creating duplicate identities.                                 |
| Refresh lost identity                  | Same origin/browser profile and site storage               | Reopen the original browser. Clearing storage loses the anonymous bearer token; the Admin cannot recover it from a hash. Never request a participant token in public chat.                                                                           |
| Submission at zero rejected            | Server deadline and expired notice                         | The server receipt time controls eligibility, including exactly at deadline. Pause/resume cannot reopen expired submissions. Host can stop or restart an unpublished round after explaining the decision.                                            |
| Duplicate submission/vote error        | Prior snapshot and locked state                            | One submission/player/round; replacement is separate and allowed only before deadline. One vote cannot be changed. Repeated IDs are safe retries; a fresh duplicate ID is rejected.                                                                  |
| Player disconnected                    | Wi-Fi, captive portal, same browser                        | Keep the tab, restore network and wait for jittered retry (up to roughly 18 s plus request timeout). Refresh only after reconnect stalls; identity remains in storage. Never resend arbitrary new commands to guess whether an action committed.     |
| Admin disconnected                     | Network, active account, eight-hour cookie                 | Restore network and reconnect/login. Do not move phases until the fresh snapshot appears. Other players keep running against server deadlines. Use audited recovery after D1 returns.                                                                |
| Projector disconnected                 | Network, code and full screen                              | Keep display URL clean. It reconnects read-only, restores current phase and retries authorized media. Refresh/F for fullscreen if necessary. Opening intermission does not pause the game.                                                           |
| Unauthorized Judge                     | Separate password/session, rotation/logout/expiry          | Admin provisions/rotates Judge credentials per manual room. Judge has no Admin APIs, publication or correction permissions. Rotation invalidates old sessions; sign in again.                                                                        |
| Too many tabs / 429                    | Same identity in multiple windows, Retry-After             | Close stale tabs; allow room presence to update. HTTP protection is per-isolate best effort, while room/socket limits are serialized in the DO. Do not work around limits with new identities.                                                       |
| Rate-limited WebSocket                 | Rapid/malformed messages                                   | Stop clicking/scripts and wait before reconnect. Close 1013 indicates temporary overload; auth failures use 1008. Thirty inbound frames per 10 s per connection is far above ordinary interaction.                                                   |
| GIF missing/failed to decode           | R2 object, file, media API response                        | Player/Admin show a stable fallback and retry; reduced motion may intentionally require Play. If 404, check source asset exists; if 401 get fresh identity/ticket; if 503 restore storage first. Never make R2 public to fix access.                 |
| Upload rejected                        | MIME, signature, file length, dimensions, configured limit | GIF/WebP/PNG/JPEG only. Default 10 MiB, configurable up to 20 MiB hard cap; max known dimensions 4096 per side / 16 MP. GIF must end in its trailer. Re-export malformed media and try a small original image.                                       |
| Upload 503                             | R2/D1 service health, request ID                           | R2 put failure creates no D1 record. D1 insert failure triggers R2 cleanup. If cleanup also fails, log `R2_CLEANUP_REQUIRED` identifies the asset UUID for private bucket/D1 reconciliation before manual deletion.                                  |
| D1 unavailable/quota                   | Dashboard and structured `service_error` / `game_error`    | Mutations fail closed; an uncommitted batch does not change authoritative data or award points. Restore quota/service, reconnect and allow same-ID retry. Avoid mass refreshes and no manual SQL score edits.                                        |
| Mirror/alarm lost                      | `CHECKPOINT_PENDING`, stored version                       | A successful D1 batch is the durable commit; its checkpoint can be repaired from the higher D1 snapshot on next load. Recovery command re-establishes the alarm and broadcasts state without undoing gameplay.                                       |
| Timer appears stuck                    | Paused, expired submission phase, manual presentation      | Question/reveal/result/leaderboard wait for Admin. Expired submissions wait for reveal. A past voting deadline is processed by DO alarm; reconnect/recovery reschedules a lost alarm against the saved deadline. Do not set client clocks to fix it. |
| Confirmation stale                     | State changed while modal open                             | Close, review the latest proposal/score and reopen. Required versions prevent old dialogs from publishing an obsolete decision.                                                                                                                      |
| Equal or zero votes                    | Preset tie rule                                            | Earliest server receipt or deterministic random selects consistently. `TALENT_DECIDES` exposes tied candidates to Admin/Judge only. No votes means every submission ties; no submissions means no winner.                                            |
| Wrong score / wrong provisional winner | Audit history and current phase                            | Override a proposal with reason/confirmation before publication. After publication use an audited score correction; totals cannot become negative. Never delete published rounds.                                                                    |

## Infrastructure recovery sequence

1. Put projector in intermission and pause if possible; preserve room and original browser identities.
2. Check Cloudflare service status, resource bindings, quota, migration version and the correct environment. Use `wrangler tail` or Dashboard logs with restricted access; application logs exclude bodies/tokens/raw errors.
3. Repair the service/configuration. Avoid schema rollback or deleting DO/D1 data. Restore a D1 backup only as a separately planned incident operation with the event stopped; old checkpoints and restored D1 must be reconciled before accepting commands.
4. Reconnect Admin, verify phase, version, submissions/votes and totals; use **Đồng bộ & khôi phục timer**. Repeated command ACKs do not add points twice. If D1 committed but a response was lost, fresh snapshots show the committed result.
5. Restore display, verify anonymous/public projections, then resume. Record any manual compensation with the correction reason in the audit.

## Local QA problems

Run real-backend suites sequentially: all use port 8790 and disposable `.wrangler/player-e2e`. Build before browser tests because Wrangler serves built assets. Apply all migrations to that same persistence path. Do not edit Worker source while a suite runs: Wrangler hot reload can disconnect sockets and invalidate timing results. Use installed Playwright browsers or `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` for system Chrome. A writable `XDG_CONFIG_HOME` avoids global Wrangler log/config permission problems on Windows.

The SQLite failure-injection harness reconstructs the actual GameSession with preserved storage/attachments; it cannot establish the cloud scheduler's real hibernation frequency. Local 30/50-browser tests use tiny original GIF fixtures and one host CPU. Rehearse real media, physical devices, venue networking, and deployed runtime behavior before event sign-off.
